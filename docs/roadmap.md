# 実装ロードマップ

- Status: **Living document** — フェーズの完了・分割の見直しに応じて更新する
- 位置づけ: 要件定義書 [§8 実装の着手順](requirements.md) を、作業チケット単位まで細分化したもの
- **GitHub Issues には未登録。** 本文書が登録元になる

## 読み方

- フェーズは**検証可能な成果**で区切っている。「完了条件」を満たさないフェーズは次に進まない
- Issue 候補 1 件は **PR 1 本**の粒度を想定している。ブランチ・PR・マージの規則は
  [CONTRIBUTING.ja.md](../CONTRIBUTING.ja.md) §6
- 「依存」は先に終わっている必要がある Issue。空欄はフェーズ内で並行可能
- 「根拠」の FR / NFR は[要件定義書](requirements.md)、C-n は[各 ADR](adr/README.md) の派生制約
- **🧑 が付いた Issue は人間が実行する。** 実機・実行環境・公開操作が必要で、AI エージェントは完了できない。
  これらは[付録](#付録-人間が実行する-issue-の本文)にそのまま貼れるチェックリスト本文がある

## P0. 足場づくり

**目的** — エラー処理・ログ・依存監査の土台を先に置く。あとから入れると全箇所の書き換えになる。
そして**最大のリスクを最初に潰す**。

**完了条件** — `cargo clippy` が通り、フィクスチャのテストハーネスが動き、Tauri が 3 OS でビルドできることが確認できている。

| ID | タイトル | 完了条件 | 依存 | 根拠 |
|---|---|---|---|---|
| P0-1 | `sdmeta-core` のエラー型を `thiserror` で定義する | 公開 API が `anyhow` / `Box<dyn Error>` を返さない。エラー種別で分岐できる | | C-6, AGENTS.md |
| P0-2 | ログ出力の基盤を入れる（ファイル出力先の決定を含む） | 3 OS それぞれの標準的なログ位置に書ける。トースト用のメッセージと分離されている | P0-1 | FR-12, C-6 |
| P0-3 | `cargo-deny` を導入し、ライセンス監査をローカルゲートに加える | GPL 系の依存が入ると落ちる。実行手順が CONTRIBUTING に載っている | | ADR-0005 |
| P0-4 | フィクスチャのテストハーネスを作る | `tests/fixtures/` を走査して全件にテストを適用できる。追加時にコード変更が不要 | | ADR-0009, verification.md |
| P0-5 | 合成フィクスチャ生成スクリプトを用意する | 構造パラメータを指定して合成パラメータ文字列を生成できる。実データを一切含まない | P0-4 | tests/fixtures/README.md |
| P0-6 | 🧑 **スパイク: Tauri 2 の空シェルが 3 OS でビルドできるか確認する** | macOS / Windows 11 / Ubuntu 24.04 で起動する。確認後は破棄してよい | | ADR-0001, ADR-0009 |

> **P0-6 を最初に置く理由。** ADR-0001 は Linux の WebKitGTK 依存を既知のリスクとして挙げている。
> これが致命的なら GUI スタックの再評価（ADR-0001 の再検討条件）になり、**コアの実装前に知る必要がある。**
> P5 まで伏せておくと、検証済みのコアの上に載せる段階で手戻りになる。
> これは本番のシェルではなく、ビルドが通るかだけを見る捨てる前提のスパイク。

## P1. 読み取り

**目的** — 要件定義書 §8-1。GUI を作らずにパーサを検証する。同時に[形式調査](research/metadata-formats.md)の「未検証」を潰す。

**完了条件** — `sdmeta dump` が手元の画像に対して動き、A1111 系・ComfyUI・その他ツールを判別して正規フィールドに写せている。

| ID | タイトル | 完了条件 | 依存 | 根拠 |
|---|---|---|---|---|
| P1-1 | PNG チャンクリーダーを実装する | `tEXt` / `zTXt` / `iTXt` / `eXIf` / `caBX` を列挙できる。破損ファイルでパニックしない | P0-1 | FR-1, FR-8 |
| P1-2 | JPEG APP セグメントリーダーを実装する | `APP1`(EXIF/XMP) / `APP11`(JUMBF) / `APP13` を列挙できる。`SOS` 位置を特定できる | P0-1 | FR-1, FR-8 |
| P1-3 | WebP RIFF チャンクリーダーを実装する | 単純形式と `VP8X` 拡張形式の両方を読める。EXIF / XMP / ICC / ALPH を識別できる | P0-1 | FR-1, FR-8 |
| P1-4 | **引用符対応トークナイザを実装する** | `Lora hashes` の引用符内 44 カンマを誤分割しない。キー語彙を決め打ちしない | P0-1 | **FR-4** |
| P1-5 | A1111 系テキストの構造分解を実装する | 正／負プロンプトと設定行を分離し、各トークンの**元文字列上の span を保持**する | P1-4 | FR-4, FR-6 |
| P1-6 | 正規フィールドモデルを定義する | Tier A/B/C を区別し、ツール固有キーを統合しない。未知キーは `unknown.*` に残る | | FR-3, C-8 |
| P1-7 | Forge / Neo アダプタを実装する | 合成フィクスチャの 31 キーすべてが正規フィールドか `unknown.*` に写る | P1-5, P1-6 | FR-3, FR-4 |
| P1-8 | 生成ツールの判別を実装する | ComfyUI / SwarmUI / InvokeAI / Fooocus / NovelAI を判別し、未知は生データ扱いにフォールバックする | P1-1, P1-2, P1-3 | FR-3, ADR-0002 |
| P1-9 | `sdmeta dump` サブコマンドを実装する | 全チャンク・全 EXIF タグ・正規フィールドを出力できる。機械可読（JSON）と人間可読の両方 | P1-7, P1-8 | §8-1 |

> **P1-4 と P1-5 がこのプロジェクトの核心。** 素朴な `split(",")` が競合ツールを壊している原因であり、
> span を保持しないと FR-6 の「再シリアライズせず差分除去」が実装できなくなる。
> ここを急ぐと P3 全体をやり直すことになる。

## P2. 検証基盤

**目的** — **書き換えを始める前に**、壊れたことを検出できる状態を作る。CI がない（[ADR-0007](adr/0007-ci-abolished-local-builds.md)）ので、ここが唯一のゲートになる。

**完了条件** — `sdmeta selftest` 1 コマンドで[検証チェックリスト](verification.md) A 節が自動実行される。

| ID | タイトル | 完了条件 | 依存 | 根拠 |
|---|---|---|---|---|
| P2-1 | 画素データのバイト列比較ヘルパを実装する | PNG の `IDAT` 連結 / JPEG の `SOS` 以降 / WebP のビットストリームを取り出して比較できる | P1-1, P1-2, P1-3 | verification.md A-1 |
| P2-2 | `sdmeta selftest` を実装する | A 節の各項目を自動判定し、失敗項目を一覧表示する。終了コードで成否が分かる | P2-1, P0-4 | verification.md §0 |
| P2-3 | 🧑 フィクスチャの必須分を揃える | 必須 8 種が存在し**すべて合成または自作画像**である。任意分は手元にあるものだけ加え、**未カバーを一覧に記録**する | P0-5 | verification.md |
| P2-4 | 破損入力に対する堅牢性テストを追加する | 途中切断・長さ不整合・巨大長さ宣言でパニックせずエラーを返す | P1-1, P1-2, P1-3 | FR-12, AGENTS.md |
| P2-5 | パーサのファジングを導入する | `cargo-fuzz` 等でトークナイザとチャンクリーダーを継続実行できる | P2-4 | FR-12 |

> **P2 を P3 より前に置く理由。** 書き出しの不具合は「画素が変わってしまった」という形で出るが、
> 目視では気づけない。先に比較基盤がないと、壊したことに気づかないまま進む。

## 登録時のラベル案

既存の `bug` / `enhancement` / `documentation` / `security` / `leak` / `fixture` に加えて、
以下を作ると絞り込みやすい。

| ラベル | 用途 |
|---|---|
| `phase:P0` 〜 `phase:P8` | フェーズ |
| `area:core` | `sdmeta-core`（パース・書き出し） |
| `area:cli` | `sdmeta-cli` |
| `area:gui` | `app/`（Tauri + React） |
| `area:build` | ビルド・リリース・依存監査 |
| `type:test` | テスト・フィクスチャ・検証 |
| `needs-hardware` | **3 実機が必要でエージェントが完了できない**（P0-6, P3-10, P8-3） |
| `blocked` | 依存 Issue が未完了 |

`needs-hardware` は実運用上とくに重要。AI エージェントに割り当ててはいけない Issue を明示する。

## マイルストーン案

フェーズをそのままマイルストーンにする。ただし **P3 完了で一度立ち止まる**ことを勧める。
CLI だけで削除が完結する状態になり、ここまでで「メタデータを確実に消す」という
中核価値は達成されている。GUI は利便性の層なので、P3 の時点で CLI 版を
`v0.0.1` として公開する選択肢もある。

# 付録: 人間が実行する Issue の本文

## P0-6 🧑 スパイク: Tauri 2 の空シェルが 3 OS でビルドできるか確認する

ラベル: `needs-hardware` `phase:P0` `area:build`

[ADR-0001](https://github.com/Masayuki-Suzuki/sd-meta-editor/blob/main/docs/adr/0001-gui-stack-tauri2.md) は Linux の WebKitGTK 依存を既知のリスクとして挙げている。
これが致命的なら GUI スタックの再評価（ADR-0001 の再検討条件）になるため、**コアの実装前に判明させる。**

**これは本番のシェルではない。** ビルドが通るかだけを見る、捨てる前提のスパイク。
`app/` には何もコミットしない。作業はリポジトリ外（例: 一時ディレクトリ）で行う。

### 前提ツールの導入

- [ ] macOS: Xcode Command Line Tools
- [ ] Windows 11: MSVC ビルドツール、WebView2 ランタイム
- [ ] Ubuntu 24.04: `libwebkit2gtk-4.1-dev` `libappindicator3-dev` `librsvg2-dev` `patchelf`

### ビルドと起動

- [ ] macOS 14.6 (arm64): ビルド成功、起動してウィンドウが表示される
- [ ] Windows 11: ビルド成功、起動してウィンドウが表示される
- [ ] Ubuntu 24.04 (x86_64): ビルド成功、起動してウィンドウが表示される
- [ ] Ubuntu: `WEBKIT_DISABLE_DMABUF_RENDERER=1` **なし**で描画が正常か
- [ ] NVIDIA GPU 環境が手元にある場合、描画崩れが出ないか

### 記録と判断

- [ ] 各 OS のツールチェーンのバージョンと、初回ビルドの所要時間を記録
- [ ] 発生した問題と回避策を記録
- [ ] **結論を出す**: WebKitGTK のリスクは許容範囲か。許容できない場合は ADR を起こす
- [ ] スパイクのコードを破棄したことを確認（リポジトリに混入していない）

## P2-3 🧑 フィクスチャの必須分を揃える

ラベル: `fixture` `phase:P2` `type:test`

[verification.md](https://github.com/Masayuki-Suzuki/sd-meta-editor/blob/main/docs/verification.md) の形式カバレッジのうち、**必須分を揃える。**
各生成ツールを動かす必要があるため人手が入る。

> **全形式を最初から揃えない。** 揃うまで待つ運用にすると検証がいつまでも始まらない。
> 任意分は手元にあるものだけ加え、残りは未カバーとして記録し、Issue が上がってから対応する。

> **最重要の制約。** フィクスチャは**合成データまたは自作画像のみ**。
> 他者の画像、および自分の実運用の生成物（LoRA 構成・マージレシピ・学習ジョブ ID を含むもの）を
> **絶対にコミットしない。** [tests/fixtures/README.md](https://github.com/Masayuki-Suzuki/sd-meta-editor/blob/main/tests/fixtures/README.md) を読むこと。
> 過去に実データをコミットして履歴から purge した経緯がある。

### 必須（これが揃うまで P3 の書き出し実装に進まない）

合成するか、標準的な CLI ツール（ImageMagick / `cjpeg` / `cwebp` / `exiftool`）で作れるもの。

- [ ] PNG: `tEXt` のみ
- [ ] PNG: `zTXt`（zlib 圧縮テキスト）
- [ ] PNG: アルファなし
- [ ] PNG: stealth 埋め込み済み（[ADR-0004](https://github.com/Masayuki-Suzuki/sd-meta-editor/blob/main/docs/adr/0004-stealth-png-removal.md) の仕様どおり自前で埋める）
- [ ] JPEG: EXIF のみ
- [ ] JPEG: プログレッシブ
- [ ] WebP: ロスレス（`VP8L`）+ EXIF
- [ ] WebP: **単純形式から `VP8X` へ昇格が必要なケース**

### 任意（手元にあるものだけ）

無いものはチェックせず、下の「未カバーの記録」に回す。

- [ ] PNG: `iTXt` / `eXIf` 併存 / インタレース / 16bit / パレット
- [ ] JPEG: XMP 併存 / IFD1 サムネイル付き / リスタートマーカーあり
- [ ] JPEG: `APP11` JUMBF（C2PA）付き ← 署名するツールが必要
- [ ] WebP: 単純ロッシー（`VP8`）/ ICC 付き / アルファ付き
- [ ] 各ツールの実出力: ComfyUI / SwarmUI / InvokeAI / Fooocus / NovelAI

### 共通の確認

- [ ] 画像サイズが小さい（256x256 程度）
- [ ] 命名規則が `<ツール名>-<バージョン>-<特徴>.<拡張子>` に従っている
- [ ] 各ファイルの出自と「なぜこの構造が必要か」が `tests/fixtures/README.md` の表に記載されている
- [ ] **実データが含まれていないことを自分で確認した**

### 未カバーの記録

- [ ] 揃わなかった形式を `tests/fixtures/README.md` の「募集中のサンプル」に列挙した
- [ ] 以後「検証済み」と書くときは、**どの形式について検証したのかを併記する**と決めた

## P3-10 🧑 C-13: 3 OS 実機でロスレス書き出しを検証する

ラベル: `needs-hardware` `phase:P3` `type:test`

**P3 のゲート。これが完了するまで P4 以降に進まない。**
派生制約 C-13 により、ロスレス書き出しパスは 3 実機すべてで検証するまで「動作確認済み」と見なさない。

Windows の「他プロセスが開いているファイルを上書きできない」挙動は実機でしか出ない。
ここを飛ばすと、GUI を載せてから Windows で保存が壊れていると判明する。

### 各 OS 共通（3 回実行する）

- [ ] macOS: `cargo fmt --all -- --check` / `cargo clippy --workspace --all-targets` / `cargo test --workspace`
- [ ] macOS: `sdmeta selftest` が全項目 PASS
- [ ] Windows 11: 同上 4 項目
- [ ] Ubuntu 24.04: 同上 4 項目

### macOS 14.6（Apple Silicon）固有

- [ ] 拡張属性が保たれる。`com.apple.quarantine` や Finder タグを付けたファイルを処理し、`xattr -l` で確認
- [ ] 大文字小文字を区別しない APFS で `photo.PNG` と `photo.png` が衝突しない
- [ ] iCloud Drive 上のファイル（未ダウンロード状態を含む）を開いたときの挙動
- [ ] 外部ボリューム（exFAT の USB など）上で保存できる

### Windows 11 固有

- [ ] **他プロセスが開いているファイルに対して、明確なエラーを返す**
- [ ] atomic rename が成立し、失敗時に元ファイルが壊れない
- [ ] パス区切りが混在しても壊れない（`\` と `/`）
- [ ] 260 文字を超える長いパスで保存できる
- [ ] 予約名（`CON` / `NUL` / `PRN` など）を含む名前で落ちない
- [ ] ウイルス対策ソフトのスキャン中に保存してもリトライが効く
- [ ] エクスプローラーのサムネイルキャッシュがファイルを掴んでいても処理できる

### Ubuntu 24.04（x86_64）固有

- [ ] 大文字小文字を区別する ext4 で `photo.PNG` と `photo.png` が別物として扱われる
- [ ] 保存後のパーミッションが umask に従い、元ファイルの権限を不正に引き継がない
- [ ] 書き込み権限のないディレクトリで、明確なエラーを返す

### 記録

- [ ] 失敗した項目と原因を本 Issue に記録
- [ ] **チェックリスト自体の不備に気づいたら [verification.md](https://github.com/Masayuki-Suzuki/sd-meta-editor/blob/main/docs/verification.md) を更新**（同じ見落としを繰り返さないため）
