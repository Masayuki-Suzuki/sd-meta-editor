# ADR-0011: C2PA / Content Credentials は削除対象に含めない

- Status: Accepted
- 日付: 2026-11-17
- 関連: [ADR-0004](0004-stealth-png-removal.md)（削除対象の網羅方針）

## Context

C2PA（Content Credentials）は、生成ツールや編集ツールが「この画像がどう作られたか」を
署名付きで埋め込む仕様である。JUMBF というコンテナで格納され、PNG では `caBX` チャンク、
JPEG では `APP11` セグメントに入る。DALL·E、Adobe Firefly、Google 系ツールが付与する。

要件定義書 FR-8 では当初これを「削除対象として扱えること」の一項目に挙げていた。
本アプリの基本方針は「消し残さない」であり、その流儀に従えば削除対象になる。

しかし C2PA は他のメタデータと性質が異なる。**これは「隠したい情報」ではなく
「開示すべき情報」である。**

生成 AI で作られた画像であることが C2PA で明示されている場合、SNS 等では
その事実を開示すべきである。明示されるものを明示することで、AI 生成物に
否定的な層にも判別しやすくなり、不要な軋轢を避けられると考える。
プロンプトやマージレシピを隠すこと（作り方の秘匿）と、AI 生成物であることを
隠すこと（出自の偽装）は、倫理的に別の行為である。本アプリは前者を支援するが、
後者は支援しない。

## Decision

**C2PA / Content Credentials を削除対象に含めない。**

- FR-8 の漏洩経路リストから C2PA JUMBF を外し、**FR-9 の保護対象に移す**
- 「全削除」プリセットを含め、すべてのプリセットで既定保持する
- 削除するオプションも v1 では提供しない

ICC プロファイルと EXIF Orientation が「剥ぐと事故になるため保護する」のに対し、
C2PA は「剥ぐべきでないため保護する」。保護の理由は異なるが、扱いは同じ既定保持とする。

## 技術的な注意点（重要）

**本アプリの編集は C2PA の署名を無効化する。** これは避けられない。

C2PA のマニフェストは、対象アセットのバイト範囲をハッシュして署名する
（hard binding）。本アプリが EXIF や tEXt チャンクを書き換えると、
そのバイト範囲が変わるため**ハッシュ検証が失敗する**。結果として検証ツールは
「署名後に改変されている」と報告する。

つまり **C2PA チャンクを保持しても、機能する開示が残るわけではない。
壊れた開示が残る。** 多くの検証実装はマニフェストの内容自体は表示するため
「AI 生成物である」という情報は読み取れるが、検証ステータスは失敗になる。

この制約に対して本 ADR は以下を定める。

- **削除しない**（上記の判断は変えない）
- **C2PA の存在を検出したら、編集前に警告を表示する。**
  「この画像には Content Credentials が含まれています。編集すると署名の検証が
  失敗するようになります」という旨を伝える
- **C2PA の内容を Raw シートで表示する**（[ADR-0006](0006-detail-sheet-for-long-lists.md) の詳細シートを使う）。
  内容を構造的に解釈はしないが、中に何が入っているかは利用者が見られるようにする

内容を見せる必要があるのは、**C2PA が「AI 生成物である」以外の情報も含みうる**ためである。
クレーム生成ツール名とバージョン、編集履歴のアクション列、署名証明書のサブジェクト
（ツールによっては作成者の識別情報を含む）、そして**クレーム時点のサムネイル画像**が
入っていることがある。保持する判断は変えないが、何を保持しているのか知らないまま
公開するのは本アプリの趣旨に反する。

## 却下した案

**削除対象に含める（当初の FR-8）** — 出自の偽装を支援することになる。上記の理由で却下。

**既定は保持し、オプションで削除できるようにする** — 一見穏当だが、
「全削除」を選ぶ利用者が意図せず C2PA も消すことになる。また削除手段を
提供する以上、その用途を是認したことになる。v1 では提供しない。

**C2PA を構造的に解釈し、識別情報だけを除いて開示部分を残す** — マニフェストは
署名されているため、部分的に書き換えれば署名は壊れる。壊れた署名を残すくらいなら
全体を保持して警告する方が正直である。実装コストも見合わない。

**編集時に C2PA を再署名する** — 署名には C2PA の信頼リストに載った証明書が必要で、
[ADR-0010](0010-no-code-signing.md) でコード署名すら行わない方針と整合しない。

## Consequences

- FR-8 の削除対象リストから C2PA が外れ、FR-9 の保護対象に移る
- FR-5 の「全削除」プリセットの意味が変わる。**「全削除」は文字どおりの全削除ではなく、
  ICC・EXIF Orientation・C2PA を除く全削除である**。UI でこれを明示する必要がある
- C2PA 検出と警告表示、Raw シートでの表示が実装項目として増える
- README の「消し残さない」の記述から C2PA を外し、保護対象として記載し直す
- 検証ステータスが失敗になる点は**既知の制限**として README に明記する。
  SynthID が除去できないことと並べて、正直に開示する
