# ADR-0006: 件数の多い一覧は詳細シート（別画面）で表示する

**Status:** Accepted
**Date:** 2026-11-12

## Context

メイン画面は左にプレビュー、右にメタデータのタブという 2 ペイン構成であり、右ペインの幅は限られる。

一方、一覧性が必要な情報が 3 種類ある。

- **LoRA 一覧** — 実サンプルでは 45 件に達した。かつ**1 件ごとに保持/削除を切り替えられる必要がある**（プリセットによる一括削除だけでは「モデル名は見せたいが LoRA は隠したい」といった部分開示の需要に応えられない）
- **Raw ダンプ** — 全チャンク・全 EXIF タグ
- **ComfyUI workflow JSON** — ADR-0002

ADR-0002 で ComfyUI の workflow を別画面に出すと決めていたが、それが
**その場限りの判断なのか、一般的な UI パターンなのか**が定義されていなかった。

## Decision

**件数の多い一覧は右ペインのタブに収めず、モーダルまたは全面オーバーレイの「詳細シート」として別画面に開く。**

- LoRA 一覧・Raw ダンプ・ComfyUI workflow は**同一のシート UI コンポーネントを共有する**
- 右ペインのタブにはサマリ（件数と代表例）と「一覧を開く」ボタンのみを置く
- 詳細な要件は要件定義書 FR-2.1 に定義する

## Rationale（却下案の記録）

| 案 | 却下理由 |
|---|---|
| **右ペインのタブ内に収める** | 幅が足りない。45 件規模ではスクロールと誤操作が増え、検索フィルタや一括操作を置く余地もない |
| **ペインを 3 分割する / 右ペインを可変幅にする** | プレビューが潰れる。本アプリは「プレビューを見ながら何を消すか判断する」用途なので本末転倒 |
| **一覧ごとに個別の UI を作る** | 同じ性質の問題を 3 箇所で別々に解くことになり、挙動のズレ（片方だけ ESC で閉じない、片方だけ検索がない）が必ず生じる |
| **別ウィンドウ（マルチウィンドウ）で開く** | Tauri でウィンドウを増やすと状態同期とフォーカス管理のコストが上がる。モーダルで要求を満たせる |

## Consequences

**得られるもの**

- 一覧に画面幅を使えるため、検索フィルタ・一括操作・検出元バッジを無理なく配置できる
- 3 箇所で挙動が揃う。シート UI を 1 度直せば全部に効く
- ADR-0002 の判断が一般原則として位置づけられ、今後の一覧追加時に迷わない

**受け入れるリスク**

- モーダルを開く 1 アクションが増える → 右ペインのサマリに件数と代表例を出し、**開かずに済むケースを減らす**ことで緩和する
- キーボード操作（ESC、フォーカストラップ）とアクセシビリティの実装が必要になる

## 本決定から派生する設計制約

### C-10. 詳細シートの行はメモ化する

1 行のトグルが一覧全体の再レンダを起こしてはならない。45 行のシートで 1 件トグルするたびに全行が
再描画されると、本プロジェクトが回避しようとしている「もっさり挙動」をそのまま再現することになる。
ADR-0001 C-2 と同じ趣旨をリスト UI に適用したもの。

### C-11. シート内の操作はプロンプト本文を書き換えうる

LoRA のトグル OFF は `<lora:name:weight>` タグの除去を伴うため、プロンプトのテキストボックスの
内容が変化する。この書き換えは**プロンプト編集と同一の Undo スタックに積み**、トグル操作も
Ctrl+Z で戻せること。バックエンドへの往復は行わない（ADR-0001 C-2）。

## 再検討のトリガー

- シートに表示する情報が増え、モーダル内でさらに階層的なナビゲーションが必要になった場合
  → 専用画面（ルーティング）への移行を検討する
