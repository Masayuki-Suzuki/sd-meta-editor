# ADR-0002: ComfyUI 画像は Raw 表示＋保持/削除トグルのみ対応する

**Status:** Accepted
**Date:** 2026-11-12

## Context

ComfyUI は PNG の `prompt` / `workflow` tEXt チャンクにノードグラフ JSON を格納する。この JSON を構造的に編集するには、ノード種別の同定（`CLIPTextEncode` 等）、widget 値の位置特定、カスタムノード・バージョン差への追従が必要であり、実装コストと破損リスクが大きい。

一方、本ツールの主要ユーザー心理は「プロンプト・使用 LoRA・生成環境を知られたくない」という**削除要求**であり、ワークフローを細かく書き換えたいという需要ではない。

## Decision

v1 では以下に限定する。

- 生成元を ComfyUI と判定した場合のみ、`Workflow` / `JSON` ボタンを表示する
- 押下すると**別画面（モーダルまたは別タブ）で Raw データを表示**する
- 操作は**チャンク単位の「残す / 消す」トグルのみ**。JSON 内部は書き換えない
- 判定不能な未知チャンクも同じ画面・同じ扱いとし、既定は「残す」（非破壊）

ノード単位のプロンプト編集は v2 以降の検討事項とし、バックログに置くだけとする。

## Rationale（却下案の記録）

| 案 | 却下理由 |
|---|---|
| ノード単位でプロンプトを編集 | 実装コストが大きく、ComfyUI のバージョン差・カスタムノードで壊れやすい。主用途（削除）に対する寄与が小さい |
| v1 では非対応（検出して警告のみ） | 削除すらできないのは主用途を満たさない |

## Consequences

**得られるもの**

- 実装コストが大幅に下がる
- JSON を壊す事故が**構造的に起き得なくなる**（バイト列として残すか捨てるかの二択のため）
- ComfyUI のバージョンアップ・カスタムノードの影響を受けない

**受け入れるリスク**

- 「workflow の一部だけ残したい」という要求には応えられない。主用途ではないため許容する

## 再検討のトリガー

- ノード単位編集の要望が Issue で継続的に挙がった場合
- ComfyUI 側にメタデータの標準化されたサブセット仕様が生まれた場合
