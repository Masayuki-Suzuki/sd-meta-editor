# ADR-0005: ライセンスに Apache License 2.0 を採用する

**Status:** Accepted
**Date:** 2026-11-12

## Context

GitHub での公開を前提としており、要件定義書 第 7 章の未決事項としてライセンス選定が残っていた。

プロジェクトオーナーの判断基準は以下。

- **改変されたことが明示されること。** 原典と区別がつかないまま改変版が流通する状態を避けたい
- **改変によって生じた不具合の責任を原著者が負わないこと**
- MIT ほど無制限に自由にはしたくない
- 個人プロジェクトであり、大規模なコントリビュータ運用は想定しない。CLA 等の運用コストは避けたい

## Decision

**Apache License 2.0 単独**を採用する。

- `LICENSE` は apache.org の公式本文を**逐語のまま**設置する（改変しない）
- 著作権表示は `NOTICE` に分離する（Apache 財団推奨の構成）
- ソースファイルには `// SPDX-License-Identifier: Apache-2.0` を付す
- **CLA は用意しない**（第 5 条により不要）

## Rationale（却下案の記録）

| 案 | 却下理由 |
|---|---|
| **MIT** | 改変の明示義務がない。特許許諾条項・商標条項・第 9 条の補償条項もない。「MIT ほど自由にはしたくない」という方針に合わない |
| **MPL-2.0** | 改変ファイルのソース公開を強制できるが、本プロジェクトはフォークの囲い込みを問題視していない。利用のハードルを上げる割に得るものが少ない |
| **GPL-3.0** | アプリ全体にコピーレフトが伝播する。目的に対して過剰であり、利用者を不必要に狭める |
| **MIT OR Apache-2.0 デュアル** | Rust ライブラリの慣行であり GPLv2 互換性を確保できるが、現時点で `sdmeta-core` を crates.io に公開する予定がない。**追加は容易・撤回は困難**なため、公開する段階で再検討する |

## 意図と条項の対応

| 意図 | 根拠条項 |
|---|---|
| 改変したことを明示させる | **§4(b)** 改変したファイルに「変更した旨の目立つ通知」を付す義務 |
| 原著者が改変後の不具合の責任を負わない | **§7** 無保証 / **§8** 責任制限 / **§9** 再配布者が独自に保証・サポートを提供する場合は自己の責任においてのみ行い、原著者を補償する義務を負う |
| プロジェクト名を勝手に使わせない | **§6** 商標 |
| 特許リスクの低減 | **§3** 特許許諾と、特許訴訟提起時の自動終了 |
| CLA を不要にする | **§5** 貢献は別段の合意がない限り本ライセンスと同一条件でライセンスされる |

## Apache-2.0 が提供しないもの（誤解を避けるための明記）

- **フォークのソース公開を強制しない。** クローズドソース化、商用利用、改変の非公開化はすべて許される
- **§4(b) は「変更した旨の通知」を求めるものであり、詳細な変更履歴や差分の保持を求めるものではない。** 改変履歴そのものを残させたい場合、Apache-2.0 では実現できない
- **無保証・責任制限は MIT にも同等の規定がある。** この点は Apache-2.0 を選ぶ差別化要因ではない
- **GPLv2 と非互換**

## Consequences

**得られるもの**

- CLA の運用が不要になる
- 改変版が原典と混同されるリスクが下がる
- 商標条項によりプロジェクト名の無断使用を抑止できる

**受け入れるコスト**

- 依存クレートを追加する際、Apache-2.0 と非互換なライセンス（GPL 系）を避ける必要がある。実装開始時に **`cargo-deny` による CI チェックを導入する**こと
- `NOTICE` の維持管理が必要になる（サードパーティ由来のコードを取り込んだ場合は帰属表示を追記する）
- GPLv2 プロジェクトから `sdmeta-core` を利用できない

## 再検討のトリガー

- `sdmeta-core` を crates.io に公開する場合 → `MIT OR Apache-2.0` デュアルライセンス化を検討する
- フォークの囲い込みが実際に問題になった場合 → MPL-2.0 を検討する
