# ADR-0010: コード署名を行わず、OS の警告の回避手順を案内する

- Status: Accepted
- 日付: 2026-11-17

## Context

macOS と Windows はどちらも、署名されていない配布物の実行を既定で妨げる。

- **macOS**: Gatekeeper が「開発元を確認できないため開けません」と表示する。
  これを解除するには Apple Developer Program（年額 99 USD）での署名と、
  Apple のサーバへ提出する notarization（公証）の両方が必要になる。
  署名だけでは不十分で、公証まで通さないと警告は消えない。
- **Windows**: SmartScreen が「WindowsによってPCが保護されました」と表示する。
  OV コード署名証明書は年額 200〜400 USD 程度、EV はさらに高い。しかも
  SmartScreen の評価はダウンロード数の蓄積で上がる仕組みのため、
  **証明書を買っても当初は警告が出続ける**ことがある。
- **Linux**: `.deb` / AppImage に署名の強制はない。この問題は存在しない。

つまり警告を消すには継続的な金銭コストがかかり、Windows については
支払っても即座に解決しない。

一方で本プロジェクトは個人開発であり、スケールする前提を置いていない
（ADR-0001 以降の判断と同様）。利用者が数人の段階で年額数百ドルを払う判断は取れない。

## Decision

**v1 では有料のコード署名証明書を取得しない。**

- macOS: ad-hoc 署名（`codesign -s -`）または自己署名で配布する。
  Gatekeeper は通らない前提とする
- Windows: 署名なしで配布する。SmartScreen の警告が出る前提とする
- Linux: 署名は不要なので何もしない

**代わりに 2 つを必ず提供する。**

1. **README とリリースノートに回避手順を明記する**（下記）
2. **各リリースに SHA-256 チェックサムを添付する。** これは無料で、
   「正規の配布物かどうか」を利用者が自力で検証する手段になる。
   コード署名の代替にはならないが、改変の検出はできる

### 案内する回避手順

**macOS**

Finder で Control クリック → 開く、という従来の手順は macOS 15 以降の
隔離属性付きアプリでは機能しない。システム設定からの操作を案内する。

```
システム設定 → プライバシーとセキュリティ → 「このまま開く」
```

コマンドラインに抵抗がない利用者向けには隔離属性の削除も案内する。

```bash
xattr -dr com.apple.quarantine "/Applications/SD Meta Editor.app"
```

**Windows**

```
「WindowsによってPCが保護されました」→ 詳細情報 → 実行
```

**Linux**

AppImage は実行権限の付与が必要。

```bash
chmod +x SD_Meta_Editor-*.AppImage
```

## 却下した案

**Apple Developer Program に加入して署名・公証する** — 年額 99 USD。
利用者数が不明な段階で払う理由がない。**本当に必要になった時点で加入すればよく、
その判断を先送りするコストはゼロである**（アプリの構造は変わらない）。

**Windows の OV 証明書を取得する** — 年額 200〜400 USD かつ、SmartScreen の
評価が蓄積するまで警告が消えない可能性がある。費用対効果が最も悪い。

**署名なしで、警告についても説明しない** — 利用者が「壊れている」「マルウェアだ」と
誤解する。メタデータを扱うツールで不信感を持たれるのは致命的であり、
説明は必須と判断する。

**自己署名証明書を利用者にインストールさせる** — 利用者に証明書ストアを
操作させるのは、署名なしより危険な習慣を教えることになる。却下。

## Consequences

- 初回起動時に利用者が必ず一手間を踏む。**導線が README と
  リリースノートに書かれていないと離脱する**ため、記載は必須とする
- 「署名されていない」ことを隠さない。セキュリティ重視のツールとして、
  現状を正確に開示する方が信頼を得やすい
- SHA-256 チェックサムの生成をリリース手順に含める
- 配布物が増える（チェックサムファイル）。[ADR-0012](0012-github-only-distribution.md) の
  GitHub Releases のみという方針と整合する

## 再検討の条件

- 利用者から警告に関する問い合わせが繰り返し発生した場合
- Homebrew cask や winget への登録を行う場合（署名が要求される可能性がある）
- 配布数が増え、SmartScreen の評価が自然に蓄積しうる規模になった場合
