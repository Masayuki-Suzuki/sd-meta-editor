# 3 OS 検証チェックリスト

- Status: **Living document** — 随時更新する（下記「この文書の更新について」）
- 根拠: [ADR-0009](adr/0009-local-builds-all-three-os.md) 派生制約 C-13
- 対象: 要件定義書 [FR-6](requirements.md)（書き出し）・FR-7（保存後検証）・FR-8（漏洩経路）・FR-9（保護対象）

## 0. この文書の位置づけ

[ADR-0007](adr/0007-ci-abolished-local-builds.md) で CI を廃止したため、**この
チェックリストが唯一の品質ゲートである。** 自動で止めてくれる仕組みはない。

そして C-13 により、ロスレス書き出しパスは **macOS 14.6 / Windows 11 /
Ubuntu 24.04 の 3 実機すべてで検証するまで「動作確認済み」と見なさない。**

### この文書の更新について

**本チェックリストは完成品ではなく、継続的に更新される。** 現時点の内容は
実装着手前に設計文書から導いたものであり、実機で動かしてみるまで
項目の過不足は分からない。

以下のような場合に更新する。ADR と違い、**この文書は書き換えてよい**
（ADR は Accepted 後に書き換えない、という運用ルールの対象外である）。

- 実機で検証して、不要な項目・抜けていた項目が判明したとき
- 新しい漏洩経路や生成ツールに対応したとき（FR-8 の追加に追随する）
- 対応 OS やそのバージョンが変わったとき
- 自動化が進み、手動項目を自動項目へ移せるようになったとき
- 実際に不具合が出たとき。**再発防止の項目を必ず追加する**

### 設計原則：手動項目を増やさない

**最大のリスクは「チェックリストが長すぎて実行されなくなること」である。**
3 OS で何十項目も手で確認する運用は、2 回目には破綻する。

したがって次の方針を取る。

- **機械的に判定できるものは `sdmeta-cli` のサブコマンドに寄せる。**
  バイト列の一致、保護対象の保持、元ファイルの不変性、出力名の規則は
  すべて自動判定できる。これらを 1 コマンドで通せるようにする
- **手動で確認するのは、人間しか見られないものに限る。**
  OS のダイアログ、Gatekeeper / SmartScreen、ドラッグ＆ドロップ、
  描画、体感速度
- 目標は **1 OS あたり自動 1 コマンド＋手動 10 分以内**

> 未実装の提案: `sdmeta selftest --fixtures tests/fixtures` で A 節をすべて自動実行し、
> 失敗項目を一覧表示する。実装順（要件定義書 §8）の早い段階で入れるほど後が楽になる。

## A. 自動検証（3 OS すべてで同一コマンドを実行）

フィクスチャ一式に対して実行し、**全項目 PASS を必須とする。**

### A-1. ロスレス性 ― 画素データのバイト列一致

これが最重要。メタデータだけを書き換えたなら、画素データは 1 バイトも変わらない。

| 形式 | 比較対象 |
|---|---|
| PNG | 全 `IDAT` チャンクを連結したバイト列 |
| JPEG | `SOS` 以降のスキャンデータ |
| WebP | `VP8` / `VP8L` チャンクのビットストリーム |

**例外は stealth 除去時の PNG のみ**（[ADR-0004](adr/0004-stealth-png-removal.md)）。
この場合はデコード後の画素値がアルファ下位 1 ビットを除いて一致することを確認する。

### A-2. 保護対象の保持（FR-9）

「全削除」プリセット適用後も以下が残っていること。

- [ ] ICC プロファイルがバイト列として一致
- [ ] EXIF Orientation の値が一致
- [ ] C2PA JUMBF がバイト列として一致（[ADR-0011](adr/0011-c2pa-not-removed.md)）

### A-3. 元ファイルの不変性（FR-6）

- [ ] 入力ファイルの SHA-256 が処理前後で一致
- [ ] 入力ファイルの mtime が変化していない

### A-4. 出力ファイル名（FR-6）

- [ ] `[元ファイル名]_edited.[元拡張子]` になっている
- [ ] 既存ファイルと衝突した場合に連番が付く
- [ ] 元の拡張子の大文字小文字が保たれる（`.JPG` → `.JPG`）

### A-5. 往復検証（FR-7）

- [ ] 保存後に読み直し、削除対象が実際に消えている
- [ ] 残すと指定したフィールドが残っている
- [ ] **第三のツールでも読める**（`exiftool` で構造エラーが出ない）

### A-6. 削除の網羅性（FR-8）

形式ごとに、該当する経路がすべて消えていること。

- [ ] EXIF 埋め込みサムネイル（IFD1）
- [ ] PNG `zTXt` / `iTXt` / `eXIf`
- [ ] XMP（`APP1` / `XMP ` チャンク）
- [ ] MakerNote / GPS
- [ ] stealth PNG（アルファ LSB、[ADR-0004](adr/0004-stealth-png-removal.md)）

### A-7. パーサの堅牢性

- [ ] 引用符内に 44 個のカンマを含む `Lora hashes`（45 件）を正しく分割する
      → `tests/fixtures/text/forge-neo-params.txt`
- [ ] 未知のキーを落とさず `unknown.*` に保持する
- [ ] 入れ子の括弧を含むマージレシピを値として壊さない
- [ ] 破損ファイル・途中で切れたファイルでパニックせずエラーを返す

### フィクスチャの形式カバレッジ

**全形式を最初から揃えることは要求しない。** 揃えられるものだけで始め、残りは
Issue が上がってから対応する。揃うまで待つ運用にすると検証がいつまでも始まらない。

A 節は **必須分すべて**と、**任意分のうち手元にあるもの**に対して実行する。

#### 必須（自力で用意できる）

合成するか、標準的な CLI ツール（ImageMagick / `cjpeg` / `cwebp` / `exiftool`）で作れる。
**これが揃わないうちは書き出しパスを実装しない。**

| 形式 | バリエーション |
|---|---|
| PNG | `tEXt` のみ / `zTXt` 圧縮 / アルファなし / stealth 埋め込み済み（仕様どおり自前で埋める） |
| JPEG | EXIF のみ / プログレッシブ |
| WebP | ロスレス（`VP8L`）+ EXIF / **単純形式から `VP8X` へ昇格が必要なケース** |

#### 任意（他ツールや外部サービスに依存する）

手元にあれば加える。無ければ**未カバーとして記録し、Issue が上がった時点で追加する。**

| 形式 | バリエーション | 入手の難しさ |
|---|---|---|
| PNG | `iTXt` / `eXIf` 併存 / インタレース / 16bit / パレット | 作れるが、これを出すツールが不明 |
| JPEG | XMP 併存 / IFD1 サムネイル付き / リスタートマーカーあり | 作れるが、実ツールの出力と一致するか不明 |
| JPEG | `APP11` JUMBF（C2PA）付き | **署名するツールが必要**（DALL·E / Firefly 等） |
| WebP | 単純ロッシー（`VP8`）/ ICC 付き / アルファ付き | 作れるが優先度が低い |
| 各形式 | ComfyUI / SwarmUI / InvokeAI / Fooocus / NovelAI の実出力 | **各ツールの実行環境が必要** |

#### 未カバーの扱い

- 未カバーの形式は [tests/fixtures/README.md](../tests/fixtures/README.md) の
  「募集中のサンプル」に列挙しておく
- **検証済みと言える範囲は、フィクスチャがある形式に限る。** 「3 OS で検証済み」と
  書くときは、どの形式について検証したのかを併記する
- 未カバー形式について不具合報告（`metadata_leak` / `sample_image` テンプレート）が
  上がったら、**まずその条件を再現するフィクスチャを追加**してから修正に入る。
  修正だけ入れて再発防止のフィクスチャを足さないのは不可

## B. OS 固有の手動確認

ここが C-13 の本題。**OS ごとにファイル I/O の挙動が違う部分**を潰す。

### B-1. macOS 14.6（Apple Silicon）

- [ ] 拡張属性が保たれる。`com.apple.quarantine` や Finder タグを付けたファイルを処理し、
      **atomic rename で xattr が落ちていないか**を `xattr -l` で確認
- [ ] 大文字小文字を区別しない APFS で、`photo.PNG` と `photo.png` が衝突しない
- [ ] iCloud Drive 上のファイル（未ダウンロード状態を含む）を開いたときの挙動
- [ ] 外部ボリューム（exFAT の USB など）上で保存できる
- [ ] Gatekeeper の警告が [ADR-0010](adr/0010-no-code-signing.md) の手順で回避できる

### B-2. Windows 11

**最も差が出る OS。C-12 を C-13 に拡張した理由がここにある。**

- [ ] **他プロセスが開いているファイルを処理しようとしたときに、
      明確なエラーを返す**（Unix と違い上書き・削除が失敗する）
- [ ] atomic rename が成立する。`MoveFileEx` 相当の置き換えが
      同一ボリューム内で動作し、失敗時に元ファイルが壊れない
- [ ] パス区切りが混在しても壊れない（`\` と `/`）
- [ ] 260 文字を超える長いパスで保存できる
- [ ] 予約名（`CON` / `NUL` / `PRN` など）を含む名前で落ちない
- [ ] ウイルス対策ソフトのスキャン中に保存してもリトライが効く
- [ ] エクスプローラーのサムネイルキャッシュがファイルを掴んでいても処理できる
- [ ] SmartScreen の警告が ADR-0010 の手順で回避できる

### B-3. Ubuntu 24.04（x86_64）

- [ ] 大文字小文字を区別する ext4 で、`photo.PNG` と `photo.png` が別物として扱われる
- [ ] 保存後のファイルパーミッションが umask に従い、元ファイルの権限を不正に引き継がない
- [ ] 書き込み権限のないディレクトリで、明確なエラーを返す
- [ ] WebKitGTK の描画が壊れない。NVIDIA 環境では
      `WEBKIT_DISABLE_DMABUF_RENDERER=1` なしで起動するかを確認
      （[ADR-0001](adr/0001-gui-stack-tauri2.md)）
- [ ] AppImage が `chmod +x` 後に起動する
- [ ] `.deb` でインストール・アンインストールできる

## E. 記録方法

PR テンプレートの「Hardware tested on」欄にチェックを入れる。
A 節で失敗があった場合は、**どの形式・どの項目が失敗したかを PR に書く。**

3 OS すべてで実行していない変更は、ロスレス書き出しパスに触っている限り
**マージしない**（C-13）。書き出しパスに触らない変更（ドキュメント、UI の
文言、パーサ単体など）は該当 OS のみで構わない。

検証の過程でこのチェックリスト自体の不備に気づいた場合は、**その場で本文書を
更新する。** 同じ見落としを次回も繰り返さないための唯一の手段である。
